# Pre-Release Translations Translator Workflow

This project uses local translation workspaces plus GitHub Actions. Translators
edit the card files locally, then upload their workspace files to the GitHub
repo. GitHub does the heavy work: importing new cards, applying mapping fixes,
building the `.ypk`, updating `test-release.json`, and writing dump files.

## Short version

1. Open your local `AutoPR.pyw` helper (or `AutoPR.py`). It opens the shared three-tab window:
   **Standard**, **Rush** and **All locales**.
2. **Standard** keeps the existing per-language MyCard refresh, local `raw2`
   translation and copy/upload workflow.
3. **Rush** operates on your selected language. Fetch/pull downloads the latest
   published Pre-Release Translations workspace and merges it into your local
   `<LANG>/Rush/raw2/rush-pre-release.cdb`. Missing English, French and Japanese
   text is then fetched using the source identity snapshot bundled in this repo.
   Select **Open Database in DataEditorX** to edit that CDB.
4. Copy Rush translations into the repo to review locally, or explicitly use
   **Upload & Push** to commit that locale's workspace and start its cloud build.
5. **All locales** shows published versions and translation/artwork gaps. Its
   source-fetch/build controls are for maintainers with the source repositories;
   ordinary translators do not need them.

The translator Rush workflow needs only Python, Git, a Pre-Release Translations checkout
and your local language folder. You do not need `ygopro-rush-duel`, MDPro3_Data,
the maintainer's Windows paths, or local artwork sources. GitHub Actions obtains
those dependencies and builds all Rush packages after a workspace upload.

`AutoPR.py --menu` retains the familiar numbered Standard actions (1–7) and
adds Rush actions for the wrapper's language (8–13). Existing Standard command
arguments remain compatible.

### Safe Rush updates

- Pre-Release Translations must be on `main` and have no uncommitted changes before a
  fetch/pull. The tool never stashes, resets or discards work automatically.
- Your edits live in `<LANG>/Rush/raw2/rush-pre-release.cdb`. The downloaded
  baseline in `Rush/Base Files` is bookkeeping; do not translate it.
- Current IDs and gameplay follow the published repository workspace. New
  cards appear and retired cards leave the local database automatically.
- Text you edited locally is retained. Unedited fields can receive newer
  published translations. A first import adopts an existing local CDB's text.
- If the same field changed on both sides, the update stops before overwriting
  either CDB. `Rush/Reports/sync.json` contains both versions for review. Accept
  published values in your local file and refresh, or use menu option 13 to
  explicitly keep local conflict values. The equivalent advanced command is
  `AutoPR.py rush-refresh --no-pull-first --keep-local`.
- Upload changes only `<LANG>/Rush/Workspace/rush-pre-release.cdb` in the repo.
  Reports and packages are built by GitHub. Copy-only never commits or pushes.
- Thai Rush follows English: submit corrections through EN. Simplified Chinese
  Rush follows upstream `RD Patch.cdb`: its local workspace is reference-only.
  Both can be refreshed/viewed but cannot upload text that the builder would
  discard. Traditional Chinese (ZH-TW) is editable.

Local `Rush/Reports/report.json` lists pending card fields/artwork gaps;
`source_text.json` explains automatic source results (or Korean manual mode).
`sync.json` records additions, removals and merge conflicts. These reports
reflect the last published/locally fetched workspace, not an independent live
check of the upstream card repository.

See [Rush pre-release cards](RUSH_PRE_RELEASE.md) for maintainer build details.

## What each folder means

Inside the GitHub repo, every workspace-based language has this shape:

```text
Shared/
  Mappings.csv

<LANG>/
  Base Files/
    test-release.cdb
    test-strings.conf
  Workspace/
    test-release.cdb
    test-strings.conf
    Reports/remaining_cn.json
  test-release.json
  version.txt
  ygopro-super-pre.ypk
```

`Workspace` is the translator input folder. This is where translated
`test-release.cdb` and `test-strings.conf` go.

`Shared/Mappings.csv` is the shared placeholder mapping file for all
workspace-based languages. It shows the English card name for context, then the
existing `str1` through `str16` columns. When you fill a `{CARD}` slot with
`self` or a card ID, the same mapping is applied to every language.

`Base Files` is generated by the workflow from the latest upstream Super-Pre
package. Do not translate in `Base Files`; it can be overwritten by automation.

`test-release.json`, `version.txt`, and `ygopro-super-pre.ypk` are release
outputs. Do not edit them by hand.

`Reports/remaining_cn.json` is a helper report from `PromptPatcher.py`. It is
useful for checking untranslated Chinese text or mapping gaps.

The `dump` branch is read-only output for humans. It shows text dumps of CDB
changes so reviewers can see what changed without opening SQLite. Do not edit
the `dump` branch.

## Local setup for translators

Install these first:

- Python 3
- Git
- GitHub Desktop or Git command line
- Access to the Pre-Release Translations GitHub repo
- A CDB editor such as DataEditorX or DB Browser for SQLite

Each translator can keep their files anywhere. The paths do not need to match
the maintainer's computer.

Recommended local folder shape:

```text
Super-Pre Translations/
  ES/
    AutoPR.py
    Mappings.csv
    raw2/
      test-release.cdb
      test-strings.conf
```

Use the matching language folder name: `DE`, `EN`, `ES`, `FR`, `IT`, `JP`,
`KR`, `PT`, or `TH`.

Copy `Tools/AutoPR_local.py` from the Pre-Release Translations repo into your local
language folder and rename it to `AutoPR.py`.

Example:

```text
Pre-Release-Translations/Tools/AutoPR_local.py
  -> Super-Pre Translations/ES/AutoPR.py
```

The helper detects the language from the folder name. If the Pre-Release Translations repo
is not in a common location, the helper asks for the repo path the first time
and saves it in `.transsuperpre_local.json` beside the language folders.

You can also set one of these environment variables:

```text
TRANSSUPERPRE_REPO=C:\path\to\Pre-Release-Translations
TRANSSUPERPRE_ROOT=C:\path\to\Pre-Release-Translations
SUPER_PRE_LOCAL_ROOT=C:\path\to\Super-Pre Translations
```

Existing checkouts named `TransSuperpre` continue to work. The helper keeps
the `.transsuperpre_local.json` preference file and `TRANSSUPERPRE_*`
environment variables for compatibility; renaming a local folder is optional.
Before fetching or publishing, the helper migrates the former official GitHub
`origin` URL to `ElderLich/Pre-Release-Translations`. Custom fork remotes are
kept. The former remote URL is retired; use the new repository URL for downloads.

If your checkout still has the older helper, obtain the update once with:

```sh
git remote set-url origin https://github.com/ElderLich/Pre-Release-Translations.git
git pull --ff-only origin main
```

SSH users can set `git@github.com:ElderLich/Pre-Release-Translations.git` instead.

## Interface, editor and progress settings

The interface follows the selected card language by default, including French
and Italian. **Settings → Interface language** can pin any of the eleven UI
languages independently of the card language. Card text is never translated by
changing the interface language. Raw source logs retain their original text.

**Open Database in DataEditorX** opens the selected Standard `raw2/test-release.cdb`
or Rush `Rush/raw2/rush-pre-release.cdb`. Fetch first if that file does not exist.
The tool detects DataEditorX from `DATAEDITORX_PATH`, PATH and common install
locations. **Settings → Database editor** supports automatic detection and
browsing to an executable anywhere on the translator's machine.

The activity panel shows an animated indeterminate bar, the current action and
available card counts. **Show log / Hide log** switches between full output and
compact activity without interrupting the job. Language, editor and log settings
are saved in `.transsuperpre_local.json` beside the language folders.

Install `Tools/AutoPR_local.pyw` alongside the `.py` wrapper, renaming it to
`AutoPR.pyw`. Double-click the `.pyw` file for a launch without a console. The
`.py` GUI entry also relaunches under `pythonw.exe` on Windows; explicit commands
and `--menu` retain their console. GUI workers and their command-line children
are hidden, while their output remains available in the activity log.

## Legacy numbered menu

The steps below describe `AutoPR.py --menu`. Opening `AutoPR.py` without arguments
uses the clickable window; the Standard tab provides the same operations.

1. Run `AutoPR.py` and choose option `1`. It first pulls the latest `main`
   branch, then refreshes your local `raw2` files and local `Mappings.csv`.
2. Edit your local `raw2/test-release.cdb`.
3. Edit your local `raw2/test-strings.conf` when prompt strings or archetype
   strings need changes.
4. Edit `Shared/Mappings.csv` in the Pre-Release Translations repo when a repeated
   `{CARD}` placeholder should be replaced automatically for every language.
5. Run `AutoPR.py`.
6. Choose option `2` to upload and push.

The refresh option first fast-forwards the Pre-Release Translations repo to the latest
`main`, then downloads the latest upstream `.ypk`, extracts fresh
`test-release.cdb` and `test-strings.conf`, merges new cards into local `raw2`,
removes stale CDB rows that no longer exist upstream, removes local
`raw2/test-update.cdb` if it exists, applies the newly pulled
`Shared/Mappings.csv`, and copies it to local `<LANG>/Mappings.csv`.

All languages download the current upstream package from
`https://cdn02.moecube.com:444/ygopro-super-pre/archive/ygopro-super-pre.ypk`.
Package and JSON metadata downloads retry up to three times, alternating with
the official `cdntx2.moecube.com` endpoint on failure. TLS certificate checks
remain enabled on both servers. Custom URL overrides do not fall back to an
unrelated source. Downloads check the advertised file size and validate the
`.ypk` ZIP checksums and required files before extraction. An incomplete or invalid download produces a clear
error instead of being reported as successful. Existing download targets are
replaced only after validation. Local `AutoPR.py` wrappers use these download
helpers from the configured repository, so updating the repository also updates
their download behavior.

Upload option `2` copies these files into the GitHub repo and pushes them:

```text
raw2/test-release.cdb -> <LANG>/Workspace/test-release.cdb
raw2/test-strings.conf -> <LANG>/Workspace/test-strings.conf
```

If you prefer GitHub Desktop, choose option `3`. That copies the files into the
repo only, then you can review, commit, and push with GitHub Desktop.

Command-line equivalents:

```powershell
py AutoPR.py refresh
py AutoPR.py upload
py AutoPR.py copy
py AutoPR.py pull
py AutoPR.py status
py AutoPR.py config
```

## What GitHub Actions does

There are three workflow types for each workspace-based language.

### Workspace sync

This runs daily, manually, and when the workflow or automation scripts change.
Plain `Shared/Mappings.csv` and `Tools/PromptPatcher.py` edits do not start
workspace syncs by themselves.

It does this:

1. Downloads the latest upstream `ygopro-super-pre.ypk`.
2. Downloads the live language `cards.cdb`.
3. Extracts fresh upstream `test-release.cdb` and `test-strings.conf` into
   `Base Files`.
4. Adds any new missing cards into `Workspace/test-release.cdb` while keeping
   existing translations.
5. Adds any missing string lines into `Workspace/test-strings.conf`.
6. Applies `PromptPatcher.py` and `Shared/Mappings.csv` to reduce repeated
   manual replacements.
7. Removes workspace `test-update.cdb` if it exists, because it is generated
   fresh during release.

### Release build

This runs after a successful workspace sync, manually, and when a translator
pushes `Workspace/test-release.cdb` or `Workspace/test-strings.conf`.

It does this:

1. Copies translated workspace files into `Base Files`.
2. Applies mappings again before packaging.

## Automatic English and French card text

The existing local **Refresh from MyCard** action (`py AutoPR.py refresh`) now
fetches missing French names/effects as well as English after importing the
latest MyCard package. The equivalent repository command is:

```powershell
python .github/scripts/tcg_autopr.py --lang fr workspace-sync
```

The authoritative card inventory still comes from the upstream package. Its
pack entries resolve to exact printed set numbers; the
[Yugipedia MediaWiki API](https://yugipedia.com/api.php) resolves those to card
pages and the importer verifies the set number is actually listed there.
French first uses `fr_name`, `fr_text` and `fr_pendulum_effect` from Yugipedia.
When those are incomplete it queries the [CodexYGO public API](https://codexygo.fr/api/card/v1/docs/?lang=en).
The search uses the verified English page title, `format=master` (or `rush`),
and `languages=en,fr`. A result must have an exact `yugipediaSlug` identity and
the correct game format. Similar names, ambiguous matches and partial Pendulum
translations are rejected. The source inventory still comes from the upstream
CDB; the API does not add arbitrary new cards. English is never substituted as
French, and missing translations remain available for manual completion.

Human-edited names and effects are preserved field by field. Only blank,
source-identical or still-Chinese fields are filled. Prompts remain owned by
`Tools/PromptPatcher.py` and `Shared/Mappings.csv` as before. Matches and gaps
are recorded in `Workspace/Reports/source_text.json` (or `raw2/Reports` for a
local refresh). Matching never adds cards outside the upstream CDB.

`candidates` counts pending cards with a printed set-code mapping; `matched`
counts complete localized source records accepted for those cards. `unmatched_ids`
lists cards still needing source text, including any with no mapping. A zero
match count is not a build failure. The `unresolved` entries explain whether
fields are missing, a printed identity did not match, or a source request failed.
The nine French entries reported on 2026-10-11 resolved to verified Yugipedia
pages but had no French fields there. CodexYGO supplied all nine complete French
records; the local and repository workspaces were updated. Their report now
records `candidates: 9`, `matched: 9`, and the exact CodexYGO source links.
Later refreshes may report zero candidates when no untranslated fields remain.

Korean names/effects are translator-managed for both Standard and Rush. No
Korean web autofill is attempted. Standard still refreshes upstream inventory,
gameplay data and the existing prompt/mapping workflow; it preserves the
translator's card names/effects. Rush may reuse reviewed Korean locale seed
translations, but does not substitute English or fetch Korean website text.
Korean source reports explicitly display `mode: manual`.

The cloud Rush build publishes upstream `sets.md` as `Shared/Rush/sets.md`.
The per-language Rush tab uses that mapping plus the published original CDB to
fetch missing EN/FR/JP fields, without a separate Rush source checkout. Existing
translations are preserved. `AutoPR.py rush-refresh --offline` skips web text
queries (repository pulling is separately controlled by `--no-pull-first`). See
[Rush pre-release cards](RUSH_PRE_RELEASE.md).
